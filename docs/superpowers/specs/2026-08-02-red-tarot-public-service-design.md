# 빨강타로 공개 서비스 전환 디자인

작성일: 2026-08-02

## 1. 결정 요약

빨강타로를 현재의 로컬 저장형 학습 MVP에서 검색 유입과 Google AdSense 수익을 중심으로 운영할 수 있는 무료 공개 웹 서비스로 전환한다.

핵심 결정은 다음과 같다.

- 핵심 사용자는 타로를 처음 배우는 사람이다.
- 모든 학습 콘텐츠와 기능은 무료로 제공한다.
- 수익 모델은 Google AdSense 단일 모델로 시작한다.
- 1순위 성과 지표는 자연 검색 방문과 광고 수익이다.
- 2순위 성과 지표는 14일 입문 코스의 시작률과 완주율이다.
- 카드 사전, 조합 해석 예제, 기초 가이드를 검색 유입의 세 축으로 삼는다.
- Google, Kakao, 이메일 일회용 인증코드 로그인을 지원한다.
- 비로그인 사용도 허용하고, 로그인하면 진도·오답·즐겨찾기를 기기 간 동기화한다.
- 해석 피드백은 AI가 아니라 근거 체크리스트와 모범 해석 비교로 제공한다.
- 광고는 홈, 정보성 콘텐츠, 학습 완료 지점에만 배치하고 학습 도중에는 표시하지 않는다.
- 현재 체리 레드와 크림색의 친근한 브랜드는 유지하되 검색과 읽기에 맞게 정보 구조를 재설계한다.

## 2. 목표와 성공 기준

### 2.1 제품 목표

검색 방문자가 카드나 배열에 대한 답을 한 페이지에서 얻고, 관련 콘텐츠를 더 읽거나 14일 코스를 시작하도록 만든다. 사용자가 14일 코스를 마치면 카드의 핵심 동사, 배열 위치, 정·역방향, 카드 관계를 근거로 3장 배열을 스스로 설명할 수 있어야 한다.

### 2.2 핵심 지표

첫 공개 기간에는 절대 목표치를 임의로 정하지 않고 기준선을 수집한다.

- 자연 검색 방문 세션
- Google Search Console의 노출수, 클릭수, 평균 클릭률
- AdSense 총수익과 페이지 RPM
- 검색 방문자의 관련 콘텐츠 이동률
- 콘텐츠에서 14일 코스로 이동한 비율
- 로그인 전환율
- 14일 코스 시작률과 완주율

검색과 광고 지표를 올리더라도 콘텐츠 만족도, 재방문, 학습 완주율이 함께 떨어지면 성공으로 보지 않는다.

### 2.3 제외 범위

첫 공개 서비스에는 다음을 포함하지 않는다.

- 유료 결제와 구독
- AI 해석 생성이나 AI 첨삭
- 커뮤니티, 댓글, 상담 예약
- CMS와 비개발자용 콘텐츠 편집기
- 미래 사건을 단정하는 운세 생성기
- 검색 유입만을 위한 자동 대량 페이지 생성
- 네이티브 모바일 앱

## 3. 사용자와 핵심 흐름

### 3.1 주요 사용자

카드 의미를 외우기 어렵고, 여러 장을 어떻게 연결해야 할지 모르는 완전 초보를 우선한다. 전문 리더용 고급 기능보다 쉬운 용어, 근거가 보이는 해석, 반복 학습을 먼저 제공한다.

### 3.2 검색 방문 흐름

1. 사용자가 Google에서 `연인 카드 역방향 연애`, `소드 3 의미`, `3장 배열 읽는 법`처럼 구체적인 질문을 검색한다.
2. 카드 상세, 조합 예제, 기초 가이드 중 가장 적합한 페이지로 진입한다.
3. 페이지 상단에서 검색 의도에 대한 짧고 직접적인 답을 얻는다.
4. 정·역방향, 분야별 의미, 상징, 흔한 오해, 실제 조합을 순서대로 읽는다.
5. 관련 카드, 관련 조합, 14일 코스 중 하나로 이동한다.
6. 저장이 필요할 때 Google, Kakao, 이메일 코드 중 하나로 로그인한다.

### 3.3 학습 흐름

1. 비로그인 상태에서도 14일 코스를 시작한다.
2. 하루 7~10분 분량으로 카드 뜻, 위치, 관계를 순차 학습한다.
3. 직접 해석을 작성한다.
4. 근거 체크리스트로 자기 해석을 점검한다.
5. 모범 해석과 가능한 대안, 조건, 흔한 오해를 비교한다.
6. 퀴즈를 풀고 복습 목록에 결과를 저장한다.
7. 로그인하면 브라우저의 진도를 계정 진도와 합친다.

## 4. 정보 구조와 URL

### 4.1 전역 내비게이션

- 홈
- 카드 사전
- 조합 예제
- 기초 가이드
- 14일 코스
- 내 학습 또는 로그인

모바일에서는 홈, 카드, 코스, 복습을 하단 내비게이션에 유지하고, 검색과 로그인은 상단에서 제공한다.

### 4.2 공개 콘텐츠 페이지

- `/cards`: 78장 카드 검색과 필터
- `/cards/[cardId]`: 카드별 고유 설명
- `/readings`: 공개 조합 예제 목록
- `/readings/[setId]`: 검색 가능한 조합 해석 사례
- `/guides`: 초보 가이드 목록
- `/guides/[slug]`: 정·역방향, 질문법, 배열법 등 기초 가이드
- `/course`: 14일 코스 소개와 시작

이 중 카드 상세, 검수된 조합 예제, 검수된 가이드, 코스 소개만 검색에 노출한다.

### 4.3 학습 전용 페이지

- `/practice/[setId]`: 단계별 상호작용 학습
- `/course/day/[day]`: 날짜별 코스 본문
- `/review`: 오답과 복습 목록
- `/me`: 계정과 진도
- `/login`: Google, Kakao, 이메일 코드 로그인
- `/auth/callback`: OAuth와 이메일 인증 완료 처리

`/readings/[setId]`는 설명형 콘텐츠의 대표 URL로 삼는다. 같은 세트를 사용하는 `/practice/[setId]`는 검색 중복을 피하도록 검색 제외 메타데이터를 사용하고, 해당 읽기 페이지를 대표 URL로 연결한다. 날짜별 코스 본문도 검색에서 제외해 가이드 페이지와의 내용 중복을 막고 순차 학습 경험을 유지한다.

### 4.4 신뢰와 운영 페이지

- `/about`: 서비스 목적과 운영 주체
- `/editorial-policy`: 콘텐츠 작성·검수 기준
- `/privacy`: 개인정보처리방침과 광고 쿠키 고지
- `/terms`: 이용약관
- `/disclaimer`: 타로 해석의 한계와 분야별 안전 안내
- `/contact`: 문의 방법
- `/ads.txt`: AdSense 승인 후 발급된 실제 게시자 정보

## 5. 핵심 화면 디자인

### 5.1 시각 방향

현재의 체리 레드, 크림 배경, 둥근 카드, 작은 스티커형 장식을 유지한다. 장식은 브랜드 인상을 만드는 범위에서 사용하고 검색창, 핵심 답, 다음 행동보다 먼저 보이지 않게 한다.

공통 원칙은 다음과 같다.

- 모바일 첫 화면에 페이지 제목, 핵심 답, 검색 또는 다음 행동을 노출한다.
- 본문 폭과 줄 길이를 제한해 긴 설명을 읽기 쉽게 한다.
- 하나의 화면에서 주 버튼은 한 가지 행동만 강조한다.
- 광고, 콘텐츠, 버튼을 색과 간격으로 명확히 분리한다.
- 카드 이름, 방향, 선택, 정답 여부는 색만으로 표현하지 않는다.
- 터치 영역은 최소 44×44 CSS 픽셀을 기준으로 한다.
- 키보드 포커스, 건너뛰기 링크, 움직임 줄이기 설정을 지원한다.

### 5.2 홈

홈은 기존의 학습 대시보드보다 탐색과 검색을 우선한다.

1. 브랜드 메시지와 카드·키워드 검색
2. 메이저, 완드, 컵, 소드, 펜타클 빠른 필터
3. 많이 찾는 카드
4. 첫 번째 광고 위치
5. 인기 초보 가이드
6. 14일 코스 진입 카드
7. 로그인 사용자에게만 이어서 학습, 최근 오답, 즐겨찾기

개인 진도가 없는 방문자에게 빈 대시보드를 먼저 보여주지 않는다.

### 5.3 카드 상세

기존 탭 중심 화면을 목차와 긴 글 섹션으로 바꾼다. 검색엔진과 사용자가 핵심 콘텐츠를 같은 HTML에서 안정적으로 읽을 수 있어야 한다.

1. 탐색 경로와 카드 제목
2. 카드 비주얼, 핵심 동사, 두 문장 요약
3. 페이지 내 바로가기 목차
4. 정방향 의미
5. 역방향 의미
6. 광고 위치
7. 연애, 재물, 건강 분야별 의미
8. 상징과 흔한 오해
9. 관련 조합 예제
10. 즐겨찾기와 14일 코스 진입

건강 섹션은 질병, 임신, 치료 결과를 단정하지 않으며 의료적 판단이 필요한 상황에서는 전문가 평가가 우선임을 안내한다.

### 5.4 조합 예제

조합 예제 페이지는 질문에 대한 결론만 제시하지 않고 해석 근거를 보여준다.

- 질문과 배열 위치
- 카드와 정·역방향
- 한 문장 요약
- 카드별 핵심 동사
- 위치에 맞춘 의미
- 강화, 충돌, 원인과 결과 등 카드 관계
- 일반적인 해석
- 가능한 대안과 해석이 달라지는 조건
- 흔한 오해와 단정하지 않는 표현
- 같은 세트로 연습하기

### 5.5 14일 코스

코스는 검색 서비스의 재방문 장치이며 다음 순서를 기본으로 한다.

1. 타로를 근거로 읽는 방법
2. 메이저 아르카나와 핵심 동사
3. 네 수트와 원소
4. 숫자 패턴
5. 코트 카드
6. 정방향과 역방향
7. 좋은 질문 만들기
8. 한 장 읽기
9. 배열 위치의 역할
10. 두 카드 연결
11. 강화와 충돌 찾기
12. 세 장을 흐름으로 읽기
13. 대안과 조건 표현하기
14. 최종 3장 해석

각 날짜는 설명, 짧은 예제, 직접 작성, 체크리스트, 모범 해석, 퀴즈로 구성한다.

### 5.6 컴포넌트 경계

화면과 동작을 다음 책임 단위로 나눈다.

- `PublicHeader`: 브랜드, 전역 탐색, 검색 진입, 로그인 상태만 담당한다.
- `SiteSearch`: 카드·가이드·조합의 검색 입력, 필터, 결과 없음을 담당한다.
- `LongFormContents`: 긴 글의 목차와 섹션 이동을 담당하며 본문 데이터 자체를 소유하지 않는다.
- `CardMeaningSections`: 카드의 핵심 답, 방향, 분야, 상징, 오해를 렌더링한다.
- `ReadingEvidence`: 조합의 카드별 근거, 위치, 관계, 대안, 조건을 렌더링한다.
- `LearningChecklist`: 사용자가 자기 해석의 근거를 점검하고 모범 해석과 비교하게 한다.
- `CourseProgress`: 14일 순서, 완료 상태, 다음 학습 이동을 담당한다.
- `ProgressStore`: 로컬 진도 읽기·쓰기와 버전 이전을 담당한다.
- `ProgressSync`: 인증된 사용자의 로컬·클라우드 병합과 재시도를 담당한다.
- `AuthPanel`: Google, Kakao, 이메일 코드 로그인과 오류 복구를 담당한다.
- `AdSlot`: 승인, 동의, 허용 위치를 모두 만족할 때만 광고를 렌더링한다.
- `ConsentManager`: 광고와 분석 동의 상태 및 철회를 관리한다.

공개 콘텐츠 컴포넌트는 인증, 광고, 분석 모듈에 의존하지 않는다. 사용자 기능과 광고 기능이 실패해도 카드와 가이드 본문은 렌더링되어야 한다.

## 6. 콘텐츠와 검색 설계

### 6.1 콘텐츠 원천

78장 카드, 150개 학습 세트, 기초 가이드는 소스 코드 안에서 타입이 있는 정적 콘텐츠로 관리한다. 공개 콘텐츠를 계정 데이터베이스에 의존시키지 않는다. 로그인이나 Supabase 장애가 있어도 모든 카드와 가이드는 정상 표시되어야 한다.

### 6.2 첫 검색 공개 범위

출시 시 다음 콘텐츠를 검색에 노출한다.

- 78장 카드 상세 전체
- 사람이 검수한 핵심 가이드 12개
- 기존 150개 중 완성도가 높은 조합 예제 30개

나머지 120개 조합은 서비스 안에서 학습에 사용할 수 있지만 검색에는 바로 노출하지 않는다. 아래 품질 기준을 통과한 페이지부터 순차적으로 사이트맵에 포함한다.

### 6.3 검색 공개 품질 기준

- 제목과 질문이 페이지 내용과 정확히 일치한다.
- 카드 ID, 방향, 배열 위치, 분석 문장이 서로 모순되지 않는다.
- 다른 조합 페이지를 단어만 바꾼 문장이 아니다.
- 한 문장 요약, 카드별 근거, 관계, 대안, 조건, 흔한 오해가 모두 있다.
- 사용자가 같은 질문을 다시 검색하지 않아도 될 정도로 독립적인 답을 준다.
- 미래, 건강, 재물 결과를 확정적으로 단정하지 않는다.
- 맞춤법과 문장 흐름을 사람이 검수한다.

### 6.4 기술 SEO

- 모든 공개 콘텐츠는 서버에서 완성된 HTML을 제공한다.
- 페이지별 고유 제목, 설명, 대표 이미지, canonical URL을 제공한다.
- `sitemap.xml`에는 검색 공개 품질 기준을 통과한 URL만 포함한다.
- `robots.txt`에서 인증 콜백과 계정 페이지를 검색 제외한다.
- 카드, 가이드, 조합 사이에 문맥 기반 내부 링크를 제공한다.
- Breadcrumb 구조화 데이터를 제공한다.
- Article 또는 FAQ 구조화 데이터는 실제 화면 내용과 일치할 때만 사용한다.
- 존재하지 않는 ID는 정상적인 404 상태와 복구 링크를 반환한다.

## 7. 광고와 개인정보

### 7.1 광고 위치

초기에는 자동 광고에 전적으로 맡기지 않고 명시적인 슬롯만 사용한다.

- 홈: 인기 카드 다음 1개
- 카드 상세: 핵심 정·역방향 설명 다음 1개
- 가이드와 조합 예제: 핵심 답을 읽은 뒤 1개
- 학습: 퀴즈와 저장을 마친 완료 화면에서만 1개

14일 코스와 `/practice/[setId]`의 진행 단계 사이에는 광고를 넣지 않는다. 고정 배너, 전면 광고, 팝업, 내비게이션과 혼동되는 광고, 광고 클릭을 유도하는 문구를 사용하지 않는다.

### 7.2 광고 컴포넌트 동작

광고 설정과 AdSense 승인이 모두 준비된 경우에만 광고 스크립트와 슬롯을 렌더링한다. 다음 상황에서는 광고 컴포넌트가 콘텐츠 흐름을 막지 않고 사라진다.

- 게시자 ID가 없음
- 사이트가 아직 승인되지 않음
- 사용자가 필요한 동의를 거부함
- 광고 차단기 또는 네트워크 오류
- 광고 응답 없음

광고가 활성화된 화면에서는 예상 크기를 확보해 레이아웃 이동을 줄이고, 광고임을 명확히 표시한다.

### 7.3 동의와 정책

- 개인정보처리방침에 Google과 제3자 광고 쿠키 사용을 명시한다.
- 적용 지역에는 Google이 요구하는 CMP 또는 인증된 CMP를 사용한다.
- 광고와 분석 동의 상태를 존중하고 철회 경로를 제공한다.
- 서비스 기능에 필요하지 않은 개인정보는 수집하지 않는다.
- 운영 전 실제 서비스 국가와 데이터 처리 구조를 기준으로 정책 문안을 별도 검토한다.

### 7.4 도메인과 AdSense 준비

공개 출시에는 운영자가 직접 소유한 표준 도메인을 사용한다. 최종 도메인은 구매 전에 운영자가 승인하고 직접 결제한다. 도메인 연결 후 다음 순서로 진행한다.

1. 프로덕션 사이트와 정책 페이지 공개
2. 루트의 `ads.txt` 제공 가능 여부 확인
3. AdSense 소유권 확인 코드 또는 메타 태그 적용
4. AdSense 사이트 심사 요청
5. 승인 확인 후 광고 슬롯 활성화

광고 승인을 받기 전에는 가짜 광고나 빈 광고 상자를 노출하지 않는다.

## 8. 인증과 사용자 데이터

### 8.1 인증 제공자

Supabase Auth를 사용해 다음 로그인을 지원한다.

- Google OAuth
- Kakao OAuth
- 이메일 일회용 인증코드

비밀번호 로그인은 제공하지 않는다. OAuth 계정을 이메일 문자열만으로 임의 결합하지 않는다. 동일 사용자인지 안전하게 확인할 수 없는 공급자 계정은 명시적인 재인증이나 계정 연결 절차를 거친다.

### 8.2 사용자 데이터 모델

최소 데이터 모델은 다음 책임으로 나눈다.

- `profiles`: 사용자 ID, 표시 이름, 생성 시각
- `lesson_completions`: 완료한 학습 ID와 완료 시각
- `quiz_attempts`: 학습 ID, 정답 여부, 응답 시각
- `favorite_cards`: 즐겨찾기 카드 ID와 저장 시각
- `study_days`: 학습 활동 날짜
- `user_state`: 마지막 학습 ID와 마지막 변경 시각

연속 학습일은 중복 저장된 숫자를 신뢰하지 않고 `study_days`를 기준으로 계산한다. 모든 사용자 테이블은 행 수준 접근 정책을 사용해 인증된 사용자가 자기 데이터만 읽고 수정하도록 제한한다.

### 8.3 비로그인 저장

비로그인 진도는 버전이 있는 로컬 저장 형식으로 관리한다. 로컬 저장소를 사용할 수 없으면 현재 세션의 학습은 계속하고 기록이 영구 저장되지 않는다고 알린다.

### 8.4 첫 로그인 병합 규칙

- 완료 학습과 즐겨찾기는 로컬과 클라우드의 합집합을 사용한다.
- 퀴즈 상태는 응답 시각이 더 최근인 기록을 사용한다.
- 기존 MVP의 시각 정보가 없는 오답은 클라우드에 해당 학습 기록이 없을 때만 가져온다.
- 마지막 학습 위치는 변경 시각이 더 최근인 기록을 사용한다.
- 학습 날짜는 합친 뒤 중복을 제거하고 연속 학습일을 다시 계산한다.
- 클라우드 저장이 확인되기 전에는 로컬 데이터를 삭제하지 않는다.
- 병합 실패 시 로컬 데이터를 유지하고 다음 로그인 또는 온라인 복귀 때 다시 시도한다.

### 8.5 오프라인과 재동기화

로그인 사용자도 최근 진도를 로컬에 캐시한다. 네트워크가 끊기면 학습 이벤트를 로컬에 보관하고, 연결이 돌아오면 멱등적으로 다시 전송한다. 같은 이벤트가 두 번 전송되어도 완료나 즐겨찾기가 중복 생성되지 않아야 한다.

## 9. 분석과 운영 관측

Google Search Console과 동의 기반 GA4를 기본으로 사용한다. AdSense 보고서는 광고 지표의 원천으로 사용한다.

수집할 제품 이벤트는 다음으로 제한한다.

- 공개 콘텐츠 조회
- 사이트 내 검색과 결과 없음
- 관련 카드·조합·가이드 이동
- 14일 코스 시작
- 로그인 완료
- 날짜별 코스 완료
- 전체 코스 완료

사용자가 작성한 자유 해석 본문은 분석 이벤트로 전송하지 않는다. 광고 수익과 학습 행동을 사용자 단위로 과도하게 결합하지 않는다.

## 10. 오류와 복구 경험

### 10.1 검색과 콘텐츠

- 결과가 없으면 검색어를 짧게 쓰는 방법, 수트 필터, 인기 카드 링크를 제공한다.
- 잘못된 카드나 조합 ID는 홈으로 강제 이동하지 않고 404 설명, 검색, 목록 링크를 제공한다.
- 관련 콘텐츠가 없으면 빈 영역 대신 카드 사전 또는 코스 링크를 제공한다.

### 10.2 인증

- OAuth 취소 시 원래 페이지로 돌아가고 비로그인 진도를 유지한다.
- 만료되거나 잘못된 이메일 코드는 재전송과 주소 수정 경로를 제공한다.
- Kakao 또는 Google 설정 오류는 다른 로그인 방식으로 바꿀 수 있게 한다.
- 로그인 콜백은 허용된 같은 서비스 내부 경로로만 이동한다.

### 10.3 저장과 네트워크

- Supabase가 실패해도 공개 콘텐츠와 현재 학습은 정상 동작한다.
- 동기화 중, 완료, 실패 상태를 짧은 상태 메시지로 알린다.
- 저장 실패는 사용자가 작성한 해석을 지우지 않는다.
- 재시도는 중복 쓰기를 만들지 않는다.

### 10.4 광고와 분석

- 광고나 분석 스크립트 오류는 페이지 오류 경계로 전파하지 않는다.
- 동의하지 않은 사용자에게 필요한 범위를 벗어난 추적 스크립트를 로드하지 않는다.
- 광고 차단 상태를 이유로 콘텐츠 접근을 제한하지 않는다.

## 11. 테스트 전략

### 11.1 단위 테스트

- 카드와 학습 세트 스키마
- 중복 ID와 끊어진 참조
- 공개 검색 품질 플래그
- 진도 파싱과 버전 이전
- 로컬·클라우드 병합 규칙
- 연속 학습일 계산
- 광고 활성화와 동의 분기
- URL과 로그인 반환 경로 검증

### 11.2 렌더링과 통합 테스트

- 78개 카드 페이지의 제목, 핵심 답, canonical, 내부 링크
- 공개 가이드와 조합의 서버 렌더링 본문
- 사이트맵과 검색 제외 페이지
- 구조화 데이터와 메타데이터
- Supabase 장애 시 공개 콘텐츠 표시
- 광고 미승인 상태에서 광고 요소 미표시

### 11.3 브라우저 종단 테스트

- 검색 → 카드 상세 → 관련 조합 → 코스 시작
- 비로그인 학습 → 로그인 → 진도 병합 → 다른 세션에서 복원
- Google, Kakao, 이메일 코드 로그인 성공·취소·오류
- 퀴즈 완료 → 오답 저장 → 복습
- 네트워크 중단 → 로컬 저장 → 온라인 복귀 → 재동기화
- 동의 허용·거부·철회에 따른 광고와 분석 동작

외부 OAuth와 AdSense 심사는 자동 테스트 환경에서 실제 공급자를 호출하지 않고 계약 테스트와 프로덕션 점검을 병행한다.

### 11.4 UX와 품질 검사

- 360px 모바일부터 넓은 데스크톱까지 주요 화면 시각 QA
- 키보드만으로 검색, 로그인, 학습, 저장 완료
- 색 대비, 포커스, 레이블, 상태 알림, 움직임 줄이기 검사
- 광고와 버튼 사이의 오클릭 위험 점검
- 실제 콘텐츠 기준 성능과 레이아웃 이동 검사

## 12. 출시 판정 기준

다음 조건이 모두 충족되어야 공개 출시로 판정한다.

- 78장 카드 페이지가 고유 제목, 핵심 답, 정·역방향, 분야별 의미를 제공한다.
- 핵심 가이드 12개와 검수된 조합 30개가 품질 기준을 통과한다.
- 카드, 가이드, 조합, 코스 사이의 주요 내부 링크가 끊기지 않는다.
- 사이트맵, canonical, 검색 제외, 404 상태가 의도대로 동작한다.
- 비로그인 진도가 새로고침 뒤 유지된다.
- Google, Kakao, 이메일 코드 로그인과 로그아웃이 동작한다.
- 첫 로그인에서 로컬 진도가 손실 없이 병합된다.
- 사용자 데이터 접근 정책이 다른 사용자의 데이터 읽기와 쓰기를 차단한다.
- 광고와 분석을 비활성화해도 전체 서비스가 정상 동작한다.
- 개인정보처리방침, 이용약관, 콘텐츠 작성 기준, 면책, 문의 페이지가 공개되어 있다.
- 운영자 소유 도메인, OAuth 리디렉션, HTTPS가 준비되어 있다.
- 자동 테스트, 접근성 검사, 모바일·데스크톱 시각 QA가 통과한다.
- AdSense 광고는 사이트 승인 이후에만 활성화된다.

- 로컬 저장 버전 이전과 첫 로그인 병합

## 14. 외부 준비 사항

다음 항목은 코드 구현과 별도로 운영자의 계정 또는 승인이 필요하다.

- 구매할 도메인 이름과 결제
- Supabase 프로젝트 소유 계정
- Google OAuth 클라이언트
- Kakao Developers 애플리케이션과 필요한 동의 항목
- 이메일 OTP 발송용 운영 SMTP
- Google Search Console 속성
- Google Analytics 속성
- Google AdSense 계정, 게시자 ID, 사이트 승인
- 공개 정책 문안의 실제 운영 정보와 연락처

이 준비가 늦어져도 콘텐츠, 학습, 로컬 진도, 광고 비활성 상태의 공개 서비스 개발과 검증은 계속할 수 있다.
